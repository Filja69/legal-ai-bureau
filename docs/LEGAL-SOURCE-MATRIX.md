## 4. Priority decision for Phase 5's "first real source"

Per brief §6 (official + stable + provenance + historical redactions + machine-readable, over raw document count): **publication.pravo.gov.ru remains the correct first target**, unchanged from the Phase 2 finding. It is the only source in this matrix that is simultaneously official, has a *documented* (not third-party-reverse-engineered) JSON API, and directly carries the historical-redaction structure `TemporalLawResolver` already models.

**Blocking item before writing the real client**: this session could not get a live HTTP response from `pravo.gov.ru` or `publication.pravo.gov.ru` (every `WebFetch` call returned `Socket is closed`, from this environment). The endpoint names (`/api/PublicBlocks/`, `/api/Categories`) and the "read-only JSON, no write methods" framing are corroborated by multiple independent search snippets, but the exact document-text retrieval contract and whether it requires an API key have **not** been confirmed against a live response. Recommend either (a) a live check from an unrestricted network before implementation starts, or (b) proceeding with a defensive client that fails loudly (not silently) on any unexpected response shape, and treating the first real sync as the actual contract-confirmation step.

Court practice and commercial databases both stay `BLOCKED`/`ADAPTER_ONLY` per brief §76-77 — not forced.

## 5. Phase 6 update — re-verification attempt

Per Phase 6 brief §7-9, re-attempted the live check before writing any further connector code. Result: **still `ADAPTER_ONLY / UNVERIFIED`**, but with a more precise diagnosis than Phase 5's. `WebFetch` against both `https://publication.pravo.gov.ru/api/PublicBlocks/` and the `http://` variant failed again with `Socket is closed`. A direct `curl -m 10` from the same environment against `https://publication.pravo.gov.ru/api/PublicBlocks/` returned HTTP status `000` (connection failure) — while the identical command against `https://api.anthropic.com` returned a normal `404` in under a second. This rules out "the tool is broken" or "the endpoint doesn't exist" as explanations: general internet egress works, but this specific `.gov.ru` host does not resolve/connect from this sandbox at the network layer.

`OfficialLawSource` (`app/sources/official/official_law_source.py`) was written to a real, defensive HTTP client in Phase 5 and is unchanged in Phase 6 — it still refuses to fabricate a result on any response shape it doesn't recognize (`SourceContractError`), and `fetch()` still refuses outright since the document-text contract was never confirmed. 21 unit tests (`tests/unit/test_official_law_source.py` + `tests/unit/test_legal_data_source_interface.py`) exercise this against a mocked transport — none of them assert anything about the real portal's actual behavior, only about this client's own parsing/failure logic.

**Status: `ADAPTER_ONLY / UNVERIFIED` — unchanged. Reason: network-level block on `.gov.ru` from this sandbox, confirmed via two independent tools (WebFetch, curl) and a working-egress control case.** No workaround (proxy, alternate mirror) was used, per brief §8.
